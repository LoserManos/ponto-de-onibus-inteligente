# Enunciado do Trabalho de Engenharia de Software

## Descrição geral

O objetivo do trabalho é aplicar conceitos e técnicas de Engenharia de Software para desenvolver uma solução tecnológica, como uma aplicação móvel ou um sistema web, que:

1. consuma obrigatoriamente dados de uma API de dados abertos;
2. ofereça um serviço útil para a sociedade;
3. trate um problema de impacto social.

Os temas possíveis incluem sustentabilidade, educação, saúde, mobilidade urbana, inclusão social, acessibilidade e segurança pública.

O projeto deve ser desenvolvido em grupos de até 5 alunos, com no máximo 1 integrante da pós-graduação por grupo. O grupo pode escolher a API, as tecnologias e o tipo de solução de acordo com o problema identificado.

O uso de Scrum é obrigatório.

## Diretrizes

### 1. Escolha da API e definição do problema

O grupo deve:

- identificar e selecionar uma API de dados abertos relevante para o problema;
- integrar efetivamente a API à solução, e não usá-la apenas como exemplo ilustrativo;
- definir um problema real ou uma necessidade social que possa ser resolvida ou melhorada pela solução.

Exemplos de fontes de dados:

- dados climáticos e ambientais;
- mobilidade urbana e transporte público;
- saúde pública;
- educação;
- segurança pública;
- dados socioeconômicos.

### 2. Desenvolvimento da solução tecnológica

A solução pode ser um aplicativo móvel ou um sistema web. O desenvolvimento deve seguir boas práticas de Engenharia de Software, incluindo:

- análise de requisitos;
- design de arquitetura;
- implementação;
- testes;
- gerenciamento de configuração;
- refatoração;
- plano de manutenção e/ou evolução.

### 3. Entregas parciais

#### Entrega 1 — Definição do problema, escolha da API e planejamento inicial

Entregar:

- documento com a descrição do problema e a justificativa para a escolha da API;
- identificação do público-alvo;
- mapa de empatia;
- estrutura inicial do backlog de funcionalidades;
- ferramenta de apoio para gestão do projeto, como GitLab, Kanban, Trello ou Taiga;
- avaliação de diagnóstico.

#### Entrega 2 — Especificação de requisitos e prototipação

Entregar:

- backlog completo no formato de user stories;
- protótipo de média e/ou alta fidelidade;
- definição das tecnologias: linguagem, banco de dados, frameworks, APIs etc.;
- definição da arquitetura inicial;
- link do repositório;
- avaliação de diagnóstico.

#### Entrega 3 — Implementação e testes

Entregar:

- arquitetura de software completa e documentada;
- solução implementada e testada;
- integração efetiva com a API de dados abertos escolhida;
- plano de testes das funcionalidades desenvolvidas;
- relatório dos testes realizados, incluindo testes unitários, de integração e/ou de aceitação;
- relatório das refatorações realizadas;
- código-fonte atualizado no repositório.

#### Entrega 4 — Artigo científico

Entrega obrigatória para os grupos da turma de pós-graduação.

O artigo deve:

- seguir o template ACM;
- usar duas colunas;
- ter de 10 a 12 páginas;
- descrever a solução proposta.

Seções obrigatórias:

1. Introdução;
2. Background;
3. Trabalhos Relacionados;
4. Proposta Desenvolvida;
5. Avaliação da Solução;
6. Discussão;
7. Ameaças à Validade;
8. Conclusão.

#### Entrega 5 — Apresentação final

Entregar:

- apresentação final com demonstração ao vivo da solução;
- evidência da integração com a API de dados abertos;
- relatório final com análise dos resultados, desafios superados e melhorias futuras.

## Avaliação

A avaliação considera:

1. qualidade da definição do problema e da escolha da API;
2. clareza e completude da especificação dos requisitos;
3. coerência e usabilidade do protótipo;
4. qualidade da implementação, incluindo arquitetura, código e integração com a API;
5. documentação e entrega dos relatórios parciais;
6. participação ativa de todos os integrantes;
7. criatividade e impacto social da solução;
8. qualidade da escrita do artigo científico, para a turma de pós-graduação.

## Considerações finais

O trabalho busca integrar o conhecimento teórico de Engenharia de Software à prática de desenvolvimento, usando dados reais para resolver problemas contemporâneos. O trabalho em equipe, a divisão de tarefas e o uso de metodologias ágeis serão incentivados para produzir uma solução relevante e útil à sociedade.
